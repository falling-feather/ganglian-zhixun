# 融岗智训 — 学生双入口与智能体协作展示建议

> **文档性质**：本文件记录讨论中形成的产品方向与设计建议，用于后续方案评审、原型设计和演示编排。除非另有代码、测试或验收记录证明，本文内容不得表述为已经实现的产品事实，也不代表正式开发任务已经建立或完成。
>
> **核心建议**：学生不是在静态清单中逐项打勾，而是在一个会随其决策持续变化的真实岗位现场中完成任务。

## 1. 设计原则

### 1.1 用两个全局入口组织学生体验

学生端建议采用两个稳定的全局入口：

- **任务工作台**：承载任务理解、材料组织、专业工具、成果生产、交付检查和过程证据。
- **岗位现场**：承载人物、事件、关系、风险、时间压力、信息变化和决策后果。

这两个入口不应设计成两个并排运行、持续争夺注意力的窗口，也不应成为彼此割裂的两套状态。学生在任一时刻聚焦一个主入口，通过明确切换进入另一入口。

### 1.2 以“当前任务”作为共同锚点

任务工作台与岗位现场必须共享同一份：

- 当前任务；
- 当前阶段；
- 已发生的世界后果；
- 当前可用材料；
- 交付要求；
- 过程与能力证据链。

当前任务是两个入口之间的共同锚点。任务不是脱离情境的待办条目，岗位现场也不是与课程目标无关的自由探索空间。

### 1.3 建立双向回流

两个入口之间应形成连续闭环：

```text
任务工作台给出目标、缺口和交付要求
→ 引导学生进入岗位现场补信息、做判断或处理事件
→ 现场中的人物回应、风险变化和决策后果写回同一状态
→ 改写任务优先级、可用材料、风险提示或交付要求
→ 学生回到工作台继续生产、修订与提交
```

只有“工作台引导进入现场”而没有“现场变化回写任务”，会使岗位现场退化为装饰性剧情；只有现场变化而没有明确任务锚点，则容易让学生失去学习目标。

### 1.4 降低注意力竞争

采用双入口而非双窗口并行，主要理由是降低学生在任务、材料、人物、事件和智能体消息之间的注意力竞争。界面应始终回答三个问题：

1. 我现在要完成什么？
2. 为什么此刻需要进入另一个入口？
3. 刚才的现场变化对任务和交付造成了什么影响？

### 1.5 分别强化两类价值

- 任务工作台应被打磨为可信、清晰、高效率的专业生产力入口，而不是普通待办列表。
- 岗位现场应被打磨为沉浸式判断与后果体验，而不是另一个信息面板。

二者的视觉语言和交互节奏可以不同，但必须由同一任务、阶段、世界状态和证据链连接。

## 2. 推荐交互流程

### 2.1 日常任务闭环

1. 学生进入任务工作台，看到当前目标、阶段、交付标准和仍缺少的关键信息。
2. 工作台指出必须到岗位现场完成的具体行动，例如核实采访对象立场、处理版权风险或判断突发事件影响。
3. 学生切换到岗位现场，系统保持当前任务锚点可见，不要求重新理解上下文。
4. 学生观察现场变化，与必要角色互动，并作出具有职业含义的选择。
5. 系统明确展示选择造成的直接结果与延迟后果。
6. 现场结果回写任务工作台，更新任务优先级、材料状态、风险等级、交付要求或可用证据。
7. 学生回到工作台完成生产、修订、治理和提交。
8. 教师复核后，最终结果同时写入世界后果与能力证据。

### 2.2 入口切换提示

每次跨入口切换都应提供一句可执行的原因，而不是只提供“工作台/现场”两个标签。例如：

- “需要确认图片授权状态，前往岗位现场联系版权方。”
- “暴雨事件已改变采访顺序，返回任务工作台调整采集计划。”
- “教师复核要求补充证据，返回岗位现场核实客流数据来源。”

### 2.3 黄金演示链

推荐把核心价值压缩为一条可看懂、可复盘的黄金演示链：

```text
学生遇到突发事件
→ 识别受影响的对象、任务与风险
→ 系统按需唤醒必要智能体
→ 智能体提供材料、风险和评价支持
→ 学生比较依据并作出决策
→ 教师复核关键高风险节点
→ 世界后果与能力证据同步更新
```

演示重点不是“同时出现多少智能体”，而是让观看者看清：事件如何改变任务，系统为何只唤醒这些智能体，学生如何利用或拒绝建议，以及决定如何产生可见后果和评价证据。

## 3. 智能体展示策略

### 3.1 学生端不展示智能体列表

学生端不应以智能体头像墙、在线列表或数量统计作为主要卖点。智能体只在对当前任务有真实帮助的关键节点出现，并回答以下内容：

- 它代表什么岗位或专业视角；
- 它依据了哪些材料、规则或已发生事实；
- 它建议学生注意什么；
- 学生可以采纳、部分采纳、补证或拒绝；
- 不同选择可能造成什么任务或世界后果。

学生看到的是“对当前决策有用的岗位视角”，不是后台系统架构的完整目录。

### 3.2 将最终决定留给学生

智能体贡献应作为可审查的建议和证据，不替学生自动完成职业判断。关键节点应允许学生：

- 查看依据；
- 请求补证；
- 比较冲突意见；
- 采纳或拒绝建议；
- 对最终选择负责。

采纳与拒绝都应进入过程证据，并在后续世界变化或教师复核中得到反馈。

### 3.3 教师端与答辩端展示协作脉络

教师端和答辩演示可提供“协作脉络”或“智能体贡献回放”，按事件顺序展示：

1. 哪个事件触发了协作；
2. 哪些智能体被按需唤醒；
3. 每个智能体的权限与可见范围；
4. 系统选择、过滤或跳过它的理由；
5. 它提供的具体贡献及依据；
6. 是否经过学生判断或教师人工复核；
7. 最终写入了哪一项任务状态、世界后果或能力证据。

该回放应突出因果链和责任边界，不以动态连线数量、调用次数或智能体总数制造“复杂即先进”的印象。

### 3.4 推荐的贡献回放摘要

单个协作节点可以统一显示为：

| 字段 | 展示问题 |
| --- | --- |
| 事件 | 为什么现在需要协作？ |
| 唤醒对象 | 为什么需要这些岗位视角？ |
| 权限范围 | 每个智能体看到了什么、不能看到什么？ |
| 筛选理由 | 为什么启用、跳过或拒绝某个智能体？ |
| 贡献 | 提供了什么材料、风险判断或评价支持？ |
| 人工决定 | 学生如何选择，教师是否复核？ |
| 状态写入 | 哪个任务、世界后果或证据发生了变化？ |

## 4. 边界

### 4.1 建议与实现事实的边界

本文只记录讨论建议，不证明以下内容已经完成：

- 双入口信息架构已经按本文细节实现；
- 现场变化已经覆盖所有任务优先级、材料和交付回写；
- 学生端的智能体依据与采纳/拒绝后果已经达到最终体验标准；
- 教师端已经具备完整的协作脉络回放；
- 黄金演示已经按本文流程重新编排并完成验收。

后续如需声明已实现，必须以对应代码、测试、浏览器验收和演示收据为依据。

### 4.2 产品边界

- 岗位现场不能变成脱离教学目标的开放世界。
- 任务工作台不能退化为静态清单或普通表单。
- 两个入口不能维护互相冲突的任务或世界状态。
- 智能体不能替代学生完成最终职业决策。
- 智能体数量、调用次数和复杂网络图不能作为独立成果。
- 教师复核必须聚焦高风险和关键证据节点，避免把所有步骤都变成人工审批。
- 答辩展示必须保留智能体权限、筛选、失败和人工复核边界，不得只展示成功贡献。

## 5. 下一步建议

以下是讨论建议，不是正式项目进度或已认领任务：

1. 先用一张状态映射表固定“当前任务、阶段、材料、交付、世界后果、能力证据”在两个入口中的同源关系。
2. 为黄金演示选择一个足以体现任务变化的突发事件，明确事件前后任务优先级、材料和交付要求的可见差异。
3. 绘制学生跨入口主路径，逐步标明进入理由、返回条件和回写结果，删除没有决策价值的切换。
4. 为每个关键节点限定必要智能体集合，并记录启用、过滤、超时、失败和人工接管规则。
5. 设计学生可理解的“视角—依据—建议—选择—后果”卡片，不直接暴露后台智能体目录。
6. 为教师端制作一条与黄金演示完全同源的贡献回放，确保事件、智能体、人工决定、任务变化、世界后果和能力证据可以互相定位。
7. 以注意力负担、任务完成连续性、关键判断质量和后果理解度作为体验验证重点，而不是以页面数量或智能体数量作为成功指标。
8. 只有在原型、测试和浏览器验收完成后，才将对应建议迁入正式实现文档或开发历史。

## 6. 核心卖点表达

推荐统一使用以下表述：

> 学生不是完成一张静态任务清单，而是在一个会随其决策持续变化的真实岗位现场中完成任务。任务工作台帮助学生专业地生产和交付，岗位现场迫使学生面对人物、事件、风险与后果；多智能体只在关键节点提供有依据的岗位视角，最终判断仍由学生作出，并由教师复核与过程证据共同留痕。
