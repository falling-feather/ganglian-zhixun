# 融岗智训 — V1.2 比赛作品产品开发规划与工时估算建议（快速收口修订版）

> **文档性质**：本文是“快速完成比赛作品本体”的修订建议，**不是已实现事实**，也不是权威项目规划中已经登记或启动的正式任务。
>
> **修订关系**：本文件不修改既有规划文件；就后续决策而言，本文以更窄的用户边界取代此前平台级 `94h / 108h` 估算。此前估算仍保留为“若建设完整可配置、可泛化平台”的历史建议，不再作为本轮执行依据。
>
> **估算口径**：以现有广泛原型约 48 小时的开发节奏为参照，大量复用现有双模式外壳、世界内核、智能体调度、权限、追踪、情境目录和测试底座，只补一条最小但完整的产品主链。

## 1. 快速收口范围

### 1.1 本轮只做

本轮严格限定为：

- **一个旗舰情境**：继续使用现有“地方文旅活动融媒体报道”旗舰情境；
- **一个代表性突发事件**：选取现有旗舰链中的一个高价值事件，不扩展第二事件；
- **2—3 个核心智能体**：只保留能分别提供材料、风险或评价支持的必要角色；
- **两个学生全局入口**：任务工作台与岗位现场；
- **一条可见状态回流**：现场事件明确改动一项任务优先级、材料、风险或交付；
- **一条教师协作回放**：完整显示事件、唤醒、筛选、权限、贡献、学生决定、教师复核和状态写入；
- **一条受教师审核的协作策略**：从真实协作记录形成候选，教师批准明确版本；
- **一次可解释复用**：在同一旗舰情境的相似条件中说明复用哪条策略、为什么适用及有哪些差异；
- **一条学生替代路径复盘**：明确区分真实路径与受控替代路径；
- **最小课程/情境配置**：只允许教师调整本主链所需的少量安全字段，不建设通用课程编辑平台；
- **必要工程回归**：只验证本轮新增链路的契约、权限、重放、恢复和关键浏览器路径。

### 1.2 明确不做

- 第二情境、第二突发事件或跨场景泛化；
- 多策略库、批量管理、策略合并或高级语义检索；
- 通用可视化课程编辑器和预设课程导入；
- 预设课程导入后的最小业务闭环；
- 智能体数量扩张或 2—3 个核心智能体之外的候选启用；
- 最终效果验证、架构优越性结论和真实样本对照；
- 真实教师、专家或学生试点；
- 答辩演示、PPT、视频、比赛材料、报名或提交；
- 性能、成本、P95、DeepSeek/科大讯飞 Live；
- 生产身份、多租户、分布式、云部署和多设备矩阵；
- 美术包、复杂动效和开放世界玩法。

发现上述需求时直接记入后续清单，不插入本轮版本。

## 3. 版本与总工时

### 3.1 建议版本

- 建议起点：**`V1.2.1`**
- 连续小版本数量：**7 个**
- 建议终点：**`V1.2.7`**
- 基础总工时：**30h**
- 建议监控上限：**36h**

`30h` 约为现有 48 小时开发历时的 `62.5%`；`36h` 上限约为 `75%`。该比例与“复用既有宽底座、只补一条窄而完整主链”的边界相称。

小版本仍遵守“一次提交、一个任务编号、一个可验收结果”。本文件只建议编号；正式执行前必须由项目负责人确认并登记。

### 3.2 阶段分配

| 阶段 | 版本 | 工时 |
| --- | --- | ---: |
| 最小契约与状态回流 | `V1.2.1—V1.2.2` | 7h |
| 学生双入口与低干扰呈现 | `V1.2.3` | 5h |
| 教师协作回放 | `V1.2.4` | 4h |
| 一条策略、审核与一次复用 | `V1.2.5` | 6h |

| 必要可靠性收口 | `V1.2.7` | 5h |
| **合计** | **7 个版本** | **30h** |

## 4. 压缩后的具体任务

### 4.1 `ARCH-005 / V1.2.1`：冻结最小主链契约

- **前置**：现有 `StateProjection`、结构化世界、调度计划、权限和追踪。
- **交付**：只为旗舰事件定义一个 `CurrentTaskAnchor` 和一个最小 `CollaborationStrategy` 契约；固定当前任务、阶段、事件、2—3 个智能体、权限、依据、学生选择、教师复核、世界后果、能力证据、版本和状态。
- **验收**：
  - 两个入口只能引用同一当前任务 ID 和状态版本；
  - 策略只能引用真实事件与协作记录；
  - 只有明确教师审核状态可以批准；
  - 不包含通用策略库、跨情境适用或任意课程字段。
- **预计工时**：`3h`

### 4.2 `GAME-003 / V1.2.2`：完成一条可见状态回流

- **前置**：`ARCH-005`。
- **交付**：选择一个现有代表性突发事件，经过学生决定和必要教师门后，只形成一条清楚可见的任务变化；例如改变任务优先级并附带一项材料或风险提示。
- **验收**：
  - 岗位现场显示事件和选择；
  - 返回任务工作台后，同一任务显示前后差异；
  - 变化由世界事件结算，前端不能直接改真值；
  - 重放结果稳定，角色私有信息不泄漏。
- **预计工时**：`4h`

### 4.3 `FE-004 / V1.2.3`：收束学生双入口和核心智能体呈现

- **前置**：`GAME-003`。
- **交付**：
  - 任务工作台、岗位现场两个全局入口；
  - 两侧固定显示同一当前任务摘要；
  - 工作台说明为什么进入现场，现场说明变化如何回流；
  - 只展示 2—3 个核心智能体的“岗位视角—依据—建议—采纳/拒绝—后果”，不展示智能体列表或数量墙。
- **验收**：
  - 桌面与移动端都只有一个主焦点；
  - 切换后任务、阶段和状态版本一致；
  - 学生能采纳、拒绝或补证，并留下过程记录；
  - 非关键节点不持续占用主界面。
- **预计工时**：`5h`

### 4.4 `DEV-001 / V1.2.4`：交付一条教师协作回放

- **前置**：`FE-004`、现有追踪投影。
- **交付**：在教师端把现有世界事件、派发计划、任务、Run、学生决定、教师复核和证据聚合成一条旗舰事件协作回放。
- **验收**：
  - 一屏可按顺序查看事件触发、入选/过滤智能体、权限范围、依据、贡献、学生选择、教师复核及任务/世界/证据写入；
  - 失败、过滤和未采纳贡献不隐藏；
  - 教师可从贡献定位根事件和最终状态变化；
  - 学生接口不能读取教师审计字段。
- **预计工时**：`4h`

### 4.5 `DEV-002 / V1.2.5`：完成一条策略审核与一次解释性复用

- **前置**：`DEV-001`、`ARCH-005`。
- **交付**：
  1. 从上述协作回放封装一条候选策略；
  2. 教师审核、标注并批准明确版本，也可禁用；
  3. 在同一旗舰情境的一个相似条件中检索该已批准策略；
  4. 展示复用版本、相似原因、条件差异、保留/调整步骤和权限复核；
  5. 学生复盘展示实际路径及一条有来源的受控替代路径。
- **验收**：
  - 模型不能批准策略、扩大权限或改写规则；
  - 只有 `approved` 版本能被建议复用；
  - 相似度不能单独触发执行；
  - 禁用后不进入新协作；
  - 替代路径不写入真实任务、世界事实或成绩；
  - 不建设第二策略和跨情境复用。
- **预计工时**：`6h`

### 4.6 `CONTENT-004 / V1.2.6`：提供最小安全配置

- **前置**：`DEV-002`、现有情境草稿—校验—发布链。
- **交付**：只允许教师配置本主链必须变化的字段：任务标题/目标、突发事件说明、2—3 个智能体启用项、教师门、任务回流文案和替代路径说明。
- **验收**：
  - 配置沿用现有草稿、修订、校验和发布；
  - 不允许修改角色身份、底层权限、系统提示词或世界处理器；
  - 断引用和缺失教师门无法发布；
  - 不提供预设课程导入、通用图形编辑或第二情境。
- **预计工时**：`3h`

### 4.7 `QA-004 / V1.2.7`：完成必要可靠性收口

- **前置**：`V1.2.1—V1.2.6`。
- **交付**：只为最小主链补齐契约、权限、状态冲突、幂等、重放、策略状态和关键浏览器路径回归；修复范围仅限本轮能力。
- **验收**：
  - TypeScript 类型检查和生产构建通过；
  - 新增测试覆盖双入口同源、状态回流、教师权限、批准/禁用、一次复用和替代路径隔离；
  - 本地确定性 E2E 跑通一个旗舰事件完整链；
  - 不执行性能、Live、真实试点、最终效果或比赛材料验证。
- **预计工时**：`5h`

## 5. 最小可接受完成线

`V1.2.7` 只有同时满足以下条件才算本轮完成：

1. 一个旗舰情境中的一个代表性突发事件可从岗位现场影响同一当前任务。
2. 学生通过两个全局入口完成一次进入现场和返回工作台。
3. 只有 2—3 个核心智能体参与，学生看见其岗位视角、依据和建议。
4. 学生采纳或拒绝后，任务或世界产生一条可见后果。
5. 教师看到一条完整协作回放并完成一次复核。
6. 该协作被封装为一条策略，教师批准明确版本。
7. 同一情境中完成一次带适用原因和差异说明的复用。
8. 学生复盘能区分实际路径与一条有来源的替代路径。
9. 教师只能配置本链所需的最小安全字段。
10. 新增链路的本地确定性回归通过。

上述完成只代表比赛作品本体的一条最小完整产品链，不代表真实效果、比赛证明、报名或发布完成。

## 6. 防止再次膨胀

- 不因已有 23 个模板就启用更多智能体。
- 不因已有第二微型情境就扩展跨场景复用。
- 不把“一次解释性复用”升级为通用策略推荐平台。
- 不把“最小配置”升级为课程创作工具。
- 不为答辩好看增加动画、数据大屏或证据包。
- 不为尚未要求的最终验证补性能、Live 或真实样本设施。
- 任一任务实际超过估算 `50%` 时，先删减同任务内的泛化能力；只有最低链路自身无法成立时才重估总工时。

## 7. 工时结论

| 指标 | 修订结论 |
| --- | ---: |
| 当前快速收口目标完成度 | **约 72%** |
| 剩余基础工时 | **30h** |
| 严格监控上限 | **36h** |
| 建议起始版本 | **`V1.2.1`** |
| 连续小版本 | **7 个** |
| 建议目标版本 | **`V1.2.7`** |

压缩的根本原因不是降低产品完整性，而是改变“完整”的定义：不再建设可配置、多场景、可泛化的平台，而是只把现有强底座收束为一条评委和用户都能实际操作、理解和复盘的旗舰产品主链。
