# 融岗智训 — 岗位现场驱动的可验证协作智能体群建议

> **文档性质**：本文记录讨论形成的创新模式建议，属于后续产品设计与验证参考，**不是已实现事实**，也不代表正式开发任务已经建立、认领或完成。
>
> **建议统一命名**：**岗位现场驱动的可验证协作智能体群**。
>
> **核心边界**：该模式不是让模型自行改写规则、权限或评价标准，而是把真实岗位现场中的协作过程转化为可检查、可审核、可复用、可禁用的版本化策略，沉淀经人类审核后可复用的协作经验。

## 1. 现状评估

### 1.1 已具备的技术底座

根据现有系统盘点，项目已经具备承载该模式的若干技术基础：

- 任务工作台与岗位现场共享任务状态、世界状态及结果反馈的双状态驱动基础；
- 智能体模板、权限边界、上下文范围和事件触发后的按需唤醒能力；
- 持久任务队列、执行记录、失败与恢复记录以及智能体贡献留痕；
- 学生决策、教师复核、过程证据链和因果回放基础；
- 多智能体完整架构、简化架构与单体方案的对照结构。

这些能力说明系统已经能够“运行一次协作并记录发生了什么”。但它们本身尚不足以形成鲜明的创新模式。

### 1.2 当前需要补齐的关键闭环

建议新增的核心不是更多智能体或更复杂的调用图，而是建立：

> **可验证协作策略沉淀闭环**

该闭环要解决四个问题：

1. 一次协作为什么这样组织；
2. 人类如何审核并决定是否保留这套协作经验；
3. 相似事件再次发生时，系统如何解释复用了什么以及为什么适用；
4. 如何通过对照数据证明这套协作策略比单智能体或固定流程更有价值。

## 2. 目标模式

“岗位现场驱动的可验证协作智能体群”建议定义为：

> 岗位现场中的真实事件触发协作需求，系统依据任务、世界状态与权限按需组织必要智能体；学生作出职业判断，教师审核协作过程及结果；经批准的协作经验被封装为版本化策略，并在相似事件中以可解释方式复用，再通过替代路径回放和对照指标持续验证其价值。

该模式的创新点不在“智能体数量多”，而在以下能力组合：

- 现场事件驱动，而非预先固定全量智能体并行；
- 权限受控，而非所有智能体共享全部信息；
- 学生决策与教师治理共同在环；
- 协作过程可追溯、可复盘、可比较；
- 经人类审核的协作经验能够版本化沉淀和解释性复用；
- 每条策略都必须接受效果、成本、风险和必要性验证。

## 3. 闭环对象与流程

### 3.1 版本化协作策略对象

建议将一次完成的协作封装为“协作策略”，至少包含以下字段：

| 对象 | 必须记录的内容 |
| --- | --- |
| 策略身份 | 策略 ID、版本、状态、来源协作记录、创建与审核时间 |
| 事件条件 | 事件类型、任务阶段、世界状态、风险等级及适用前提 |
| 参与智能体 | 实际参与者、岗位职责、唤醒顺序及未参与候选 |
| 权限范围 | 每个智能体可见的数据、可调用工具、可执行动作与禁止范围 |
| 协作依据 | 触发事实、材料、规则、证据和上下文引用 |
| 智能体建议 | 每个智能体的贡献、置信边界、冲突意见与补证要求 |
| 学生决定 | 采纳、部分采纳、拒绝或补证，以及学生说明 |
| 教师复核 | 审核结论、修改意见、风险处置和批准范围 |
| 状态结果 | 对当前任务、世界后果和交付要求的实际写入 |
| 能力证据 | 形成或更新的能力维度、过程证据及评价引用 |
| 复用条件 | 允许复用的相似条件、禁止复用条件和必须重新审核的变化 |
| 验证摘要 | 相对基线的质量、效率、风险、成本与人工负担结果 |

协作策略必须引用真实发生的协作记录，不能根据模型概括自动生成一条“看起来合理”的成功经验。

### 3.2 建议的完整流程

```text
岗位现场出现事件
→ 识别受影响的任务、角色、风险和证据缺口
→ 按模板、权限和适用条件筛选必要智能体
→ 智能体分别提供有依据的建议或补证请求
→ 学生采纳、部分采纳、拒绝或继续补证
→ 教师复核关键协作节点与高风险结果
→ 任务、世界后果和能力证据写入同一状态链
→ 将本次协作封装为候选版本化策略
→ 教师标注并批准、退回、禁用或淘汰
→ 相似事件中解释性复用已批准策略
→ 通过学生复盘与架构对照持续验证
```

### 3.3 相似事件中的解释性复用

每次复用必须向教师留下可检查说明，必要时向学生提供简化说明：

- 复用了哪一条策略及哪个版本；
- 当前事件与原事件在哪些条件上相似；
- 哪些条件发生变化；
- 为什么当前仍适用；
- 哪些智能体、权限或步骤被调整；
- 哪些部分因风险、课程或角色差异没有复用；
- 是否需要教师重新批准。

系统不得仅以“相似度达到阈值”为理由静默套用策略。相似度可以辅助检索，但不能替代适用性解释和权限复核。

## 4. 教师治理

### 4.1 教师的策略治理动作

教师建议拥有以下明确动作：

| 动作 | 含义 |
| --- | --- |
| 审核 | 检查事件条件、参与者、权限、依据、学生决定、后果与证据是否完整 |
| 标注 | 补充适用课程、能力目标、风险等级、典型错误和教学价值 |
| 批准 | 允许指定版本在明确条件内被检索和建议复用 |
| 退回 | 要求补充依据、修正权限、调整步骤或重新验证 |
| 禁用 | 暂停策略进入新协作，但保留历史记录和既有引用 |
| 淘汰 | 终止后续复用，记录原因、替代策略和生效时间 |

### 4.2 状态建议

策略可采用以下受控状态：

```text
candidate
→ under_review
→ approved
→ disabled
→ retired
```

- 只有 `approved` 版本可以进入自动检索和复用建议。
- `disabled` 与 `retired` 不得从历史记录中删除。
- 已批准策略发生事件条件、权限、智能体职责、评价标准或写入效果变化时，必须生成新版本并重新审核。
- 教师批准的是明确版本和适用范围，不是对未来所有变体的永久授权。

### 4.3 人类审核不可被模型替代

模型可以协助整理候选策略、发现相似案例或提示缺失字段，但不得自行：

- 批准策略；
- 扩大权限；
- 修改课程规则或评价标准；
- 把不利结果删除或改写为成功；
- 将一次偶然成功提升为通用策略；
- 绕过学生决策或教师复核直接写入高风险世界后果。

## 5. 学生复盘

学生复盘不应只显示“正确答案”，而应帮助学生理解协作选择与职业后果。

### 5.1 必须展示的复盘内容

- 当时发生了什么事件，哪些对象受到影响；
- 系统为什么唤醒这些智能体，又为什么没有唤醒其他智能体；
- 各智能体依据什么提出了哪些不同建议；
- 学生采纳、拒绝或补证了什么；
- 教师在哪个节点进行了复核；
- 实际决策如何改变任务、材料、交付、人物关系、风险或世界结果；
- 形成了哪些能力证据。

### 5.2 替代路径与后果

复盘建议展示至少一条具有教学意义的替代路径：

```text
实际路径：学生选择 A
→ 产生后果 A1
→ 形成能力证据 A2

替代路径：如果选择 B
→ 可能触发后果 B1
→ 需要补充证据 B2
→ 风险或交付要求如何变化
```

替代路径必须来自规则、已验证模拟、教师设计或真实历史案例，并标明来源。不得让模型把未经验证的想象结果当作确定世界事实。

## 6. 验证指标

该模式必须与单智能体或固定流程进行对照，不能只展示复杂协作图。

### 6.1 建议的对照组

| 组别 | 含义 |
| --- | --- |
| 单智能体组 | 由一个通用智能体完成建议与支持 |
| 固定流程组 | 按预设步骤调用固定角色，不根据事件条件筛选 |
| 协作策略组 | 依据岗位现场、权限和已审核策略按需组织智能体 |

### 6.2 建议的核心指标

| 维度 | 指标示例 |
| --- | --- |
| 决策质量 | 关键事实引用正确率、风险识别率、补证充分度、教师评分 |
| 任务结果 | 交付达标率、返工次数、任务完成率、世界负面后果 |
| 协作必要性 | 有效贡献率、无关调用率、重复建议率、冲突解决率 |
| 权限与安全 | 越权次数、私有信息泄漏、高风险漏判、人工接管率 |
| 学生学习 | 主动追问、依据表达、建议辨别、计划修订、复盘迁移表现 |
| 教师负担 | 配置、干预、复核与终评时间，必要人工操作次数 |
| 性能与成本 | 总延迟、关键路径延迟、Token、模型调用次数和失败成本 |
| 策略复用 | 检索命中率、适用性批准率、复用成功率、禁用/淘汰原因 |

任何“协作策略更优”的结论都必须同时说明样本、任务条件、评价者、失败结果和限制。若质量没有改善或教师负担、延迟、成本显著增加，应合并角色、缩短流程或淘汰策略。

## 7. 风险边界

### 7.1 不得越过的边界

- 不让模型自行改写策略状态、权限、课程规则或评价标准。
- 不把一次成功运行直接沉淀为已批准策略。
- 不以智能体数量、调用量、连线复杂度替代价值证明。
- 不允许策略复用绕过当前任务、角色、权限和世界状态检查。
- 不因复用历史策略而忽略当前材料、事实版本或风险变化。
- 不删除被拒绝、禁用、淘汰或产生不利结果的历史。
- 不把替代路径模拟写成真实发生的学生行为或确定结果。
- 不让策略推荐替代学生最终判断和教师高风险复核。

### 7.2 需要持续观察的风险

- 历史策略固化旧规则或旧偏见；
- 相似事件检索错误导致错误迁移；
- 教师审核工作量超过教学收益；
- 学生机械接受“已审核策略”，反而降低独立判断；
- 策略版本过多、边界重叠，造成选择与维护困难；
- 为追求对照优势而隐藏失败、越权、延迟或成本。

## 8. 建议的最小实施范围

以下内容是建议，不是正式进度或已认领任务。

### 8.1 最小场景

先选择黄金演示中的一个高价值突发事件，只覆盖：

- 一种明确事件条件；
- 一个当前任务与一个任务阶段；
- 2—3 个确有独立贡献的智能体；
- 一次学生采纳或拒绝；
- 一次教师复核；
- 一项世界后果写入；
- 1—2 项能力证据更新；
- 一条可解释的相似事件复用。

### 8.2 最小策略能力

第一阶段只实现：

1. 从真实协作记录生成结构化候选策略；
2. 固定事件、权限、依据、建议、学生决定、教师复核、后果与证据引用；
3. 教师执行审核、标注、批准、禁用和淘汰；
4. 已批准版本的只读检索；
5. 复用时显示策略版本、适用原因和差异；
6. 学生复盘显示实际路径与一条有来源的替代路径；
7. 对单智能体、固定流程和协作策略进行同条件比较。

第一阶段不建议加入模型自动改写策略、自动扩大适用范围、跨课程自由迁移或无人审核的自动执行。

### 8.3 最小验收问题

最小实施完成后，至少应能回答：

- 这条策略来自哪次真实协作？
- 为什么这些智能体必须参与？
- 每个智能体看到了什么、不能看到什么？
- 学生如何使用或拒绝了建议？
- 教师批准了哪个明确版本和适用范围？
- 相似事件复用时，系统为何判断它适用？
- 任务、世界后果和能力证据具体发生了什么变化？
- 相对单智能体与固定流程，质量、风险、负担、延迟和成本是否更好？

只有这些问题都能由记录、回放和对照结果回答时，“岗位现场驱动的可验证协作智能体群”才从命名和概念进入可验证的产品模式。
