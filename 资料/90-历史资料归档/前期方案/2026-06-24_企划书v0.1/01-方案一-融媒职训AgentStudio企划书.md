版本：v0.1  
整理日期：2026-06-24  
对应榜题：XA-202603  
发榜单位：科大讯飞  
申报单位：浙江传媒学院（拟）  
赛道：学生赛道  

## 一、项目概述

### 1.1 项目名称

**融媒职训 Agent Studio：面向智能融媒体内容生产与治理专业群的岗位实训智能体开发平台**

### 1.2 一句话定义

融媒职训 Agent Studio 面向职业院校专业群教师，将岗位标准、课程标准和实训案例转化为可运行的“岗位工单智能体”，帮助教师快速搭建融媒体内容生产与治理实训任务，记录学生训练过程，生成岗位技能评价，并反向支持专业群课程与实训资源建设。

### 1.3 设计边界

本项目不是一个让学生直接生成稿件、视频或脚本的 AIGC 工具，也不是就业指导平台。项目重点是：

- 教师如何建设实训任务；
- 学生如何完成岗位训练；
- 系统如何评价岗位技能；
- 训练数据如何反馈专业群建设。

第一版以“智能融媒体内容生产与治理专业群”为验证样例，后续可扩展到影视制作、直播运营、数字出版、文化传播等专业群。

## 二、核心洞察

### 2.1 痛点一：职业院校融媒体专业群更新快，但实训任务更新慢

融媒体岗位变化很快。AIGC 写作、图像生成、短视频脚本、内容审核、版权合规、平台分发和数据复盘已经成为岗位日常，但不少实训课程仍停留在传统采写编评或单一作品制作。教师不是不知道要更新，而是缺少稳定的方法把岗位变化转成课程任务。

### 2.2 痛点二：学生会用 AI，但不一定会完成岗位任务

学生可以用 AI 生成标题、脚本、图片或文案，但职业教育要培养的不是“会生成”，而是：

- 会判断事实是否准确；
- 会识别版权和合规风险；
- 会按平台规则修改内容；
- 会根据数据复盘优化选题；
- 会解释自己的判断依据。

如果没有任务约束和过程评价，AI 反而可能削弱训练效果。

### 2.3 痛点三：实训评价常看最终作品，缺少过程证据

融媒体实训常以作品或报告作为评分依据，但作品背后的选题过程、资料核验、提示词修改、审核判断、发布策略和数据复盘很少被完整记录。教师难以判断学生到底掌握了哪些岗位技能。

### 2.4 痛点四：专业群建设缺少数据反馈

专业群建设需要证明课程体系和岗位能力之间的关系。现实中，学生实训结果常停留在课程成绩层面，很难汇总为“专业群能力画像”，也难以反向指导课程、实训项目和岗课赛证融通建设。

## 三、赛题贴合度

| 赛题关键词 | 本项目回应 |
| --- | --- |
| 职业教育 | 面向高职、职业本科等融媒体、数字媒体、新闻采编、网络直播与运营相关专业群 |
| 高水平专业群建设 | 将岗位能力映射到课程模块、实训工单、评价指标和专业群改进建议 |

| 智能体开发 | 提供可配置的多角色智能体模板和工单智能体生成流程 |

## 四、解决方案

### 4.1 产品架构

平台由五个模块组成：

1. **岗位能力图谱生成器**
   - 输入岗位 JD、职业技能标准、课程标准和实训任务；
   - 输出岗位能力点、课程映射和训练指标。

2. **工单智能体生成器**
   - 将能力点转化为可发布的实训工单；
   - 自动生成背景、材料、任务目标、交付物、评分 Rubric。

3. **多角色实训智能体**
   - 以主编、事实核查员、平台审核员、运营经理、版权顾问等角色引导学生训练；
   - 采用追问式指导，避免直接替学生完成任务。

4. **过程证据链评价系统**
   - 记录学生选题、检索、核查、修改、提交、答辩全过程；
   - 基于 Rubric 给出可解释评价，并保留教师复核。

5. **专业群诊断看板**
   - 汇总班级与专业群训练结果；
   - 输出课程缺口、实训资源缺口和下一轮工单建设建议。

### 4.2 平台工作流

教师侧：

1. 导入岗位与课程资料；
2. 选择专业群和岗位方向；
3. 生成岗位能力图谱；
4. 选择智能体模板；
5. 生成并修改实训工单；
6. 发布给学生；
7. 查看评价结果和专业群反馈。

学生侧：

1. 接收岗位工单；
2. 阅读材料包；
3. 在智能体引导下完成任务；
4. 提交脚本、核查报告、审核意见或复盘方案；
5. 接受 Rubric 评价；
6. 根据反馈完成修改。

## 五、首个样板专业群

### 5.1 专业群名称

**智能融媒体内容生产与治理专业群**

可对应职业教育专业：

- 新闻采编与制作；
- 网络与新媒体；
- 网络直播与运营；
- 数字媒体技术；
- 数字出版；
- 传播与策划。

### 5.2 岗位群

| 岗位 | 训练重点 |
| --- | --- |
| 融媒体内容策划 | 选题判断、用户画像、传播目标、脚本结构 |
| AIGC 内容审核员 | AI 生成内容识别、风险判断、修改建议 |

## 六、样板工单

### 工单一：AIGC 图文内容事实核查

任务背景：

某融媒体账号准备发布一篇由 AI 辅助生成的科普图文。编辑部担心内容中存在事实错误、出处缺失和版权风险，要求学生完成发布前核查。

学生任务：

- 标注疑似事实错误；
- 查找可信来源；
- 判断图片版权风险；
- 给出修改建议；
- 形成发布前审核意见。

智能体角色：

- 主编智能体：说明发布目标和受众；
- 事实核查智能体：追问证据来源；
- 版权顾问智能体：提示授权风险；
- 平台审核智能体：检查违规风险；
- 评价官智能体：按 Rubric 评分。

评价维度：

- 核查路径是否清楚；
- 证据来源是否可信；
- 风险判断是否准确；
- 修改建议是否可执行；
- 审核意见是否规范。

### 工单二：短视频脚本生成与审校

任务背景：

某地方文旅账号需要发布一条 90 秒短视频。学生可以使用 AI 辅助生成脚本，但必须完成事实核验、表达优化、平台适配和风险审校。

学生任务：

- 完成选题定位；
- 使用 AI 生成脚本草案；
- 修改脚本结构和口语表达；
- 标注事实来源；
- 输出发布标题、封面文案和风险说明。

评价维度：

- 选题是否明确；
- 脚本是否适合短视频；
- AI 内容是否经过审校；
- 事实和版权是否可追溯；
- 发布策略是否合理。

### 工单三：平台内容数据复盘

任务背景：

某账号连续发布三条短视频后，播放量、完播率和互动率差异明显。学生需要分析数据，找出内容问题，并提出下一轮选题建议。

学生任务：

- 阅读数据包；
- 比较三条内容表现；
- 判断影响传播效果的因素；
- 提出优化方案；
- 输出复盘报告。

评价维度：

- 数据解读能力；
- 传播逻辑判断；
- 复盘结论是否有证据；
- 优化建议是否具体；
- 能否形成下一轮选题。

### 工单四：公共传播内容风险审查

任务背景：

某校园/社区公共传播账号计划发布一组应急提醒内容。学生需要判断表达是否准确、是否可能引发误解、是否符合公共传播规范。

学生任务：

- 审核文本和图片；
- 标注潜在误导点；
- 给出更稳妥的表达；
- 形成风险等级和修改意见。

评价维度：

- 公共表达准确性；
- 风险识别；
- 受众理解；
- 修改意见；
- 合规意识。

## 七、智能体设计

| 智能体 | 作用 | 设计原则 |
| --- | --- | --- |
| 主编智能体 | 发布任务、明确传播目标 | 给场景，不给答案 |
| 事实核查智能体 | 追问来源和证据 | 要求学生说明核查路径 |
| 版权顾问智能体 | 提示素材授权和引用风险 | 提醒风险，不替代判断 |
| 平台审核智能体 | 模拟平台规则审查 | 给出规则依据 |
| 运营复盘智能体 | 分析数据和用户反馈 | 引导学生形成下一轮策略 |
| 专业群顾问智能体 | 汇总训练结果 | 输出课程与实训改进建议 |

## 八、项目创新点

### 8.1 从“AI 生成内容”转向“AI 时代的内容岗位训练”

项目不鼓励学生直接依赖 AI 完成作品，而是训练学生审校 AI 输出、核验事实、识别风险、复盘传播效果。

### 8.2 从“实训任务书”升级为“工单智能体”

教师不再只发布静态任务书，而是通过系统生成一个包含角色、材料、过程指导和评价规则的岗位工单智能体。

### 8.3 从“最终作品评分”转向“过程证据链评价”

系统记录学生如何检索、判断、修改和提交，使评价更接近职业岗位中的真实工作过程。

### 8.4 从“单门课程”反馈到“专业群建设”

训练结果不仅给学生个人，也反馈给教师和专业群负责人，帮助判断课程、实训和岗位能力之间的缺口。

## 十、项目难点与应对

| 难点 | 应对策略 |
| --- | --- |
| 方向容易变成普通 AIGC 工具 | 强调审校、核查、复盘和专业群反馈 |
| 实训案例真实性不足 | 引入公开平台规则、真实岗位 JD、脱敏内容案例 |
| AI 评价可信度不足 | 使用 Rubric、证据链和教师复核 |
| 平台型项目容易显得抽象 | 以智能融媒体专业群做首个样板，展示完整工单 |
| 涉及内容审核可能敏感 | 使用模拟/脱敏案例，不处理真实敏感事件 |

## 十四、项目优势总结

本方案的优势在于，它不依赖某个单一题材，而是提出一种职业教育智能体开发范式；同时又以浙传擅长的融媒体内容生产与治理作为首个样板，保证方案不空、不泛。它既贴合科大讯飞“智能体开发”的技术方向，也回应职业教育“专业群建设、教学实训、岗位技能评价”的核心要求。
