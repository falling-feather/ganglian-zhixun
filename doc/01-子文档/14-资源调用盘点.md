## 1. 结论和盘点口径

**后续实现承接（2026-09-11）**：自然会话覆盖已从旧的3个专用角色扩至当前课内10个人物；公示、商户与公共资料点可独立探索，12种调查策略、两组多项取舍、离场续访和邮件补发进入持久世界。原32步人物计划按新采访事件同步，授权SQL资料进入人物问答；两份官方PDF已实际解析449个片段。资料可进入原作品引用，教师可查看实际过程。当前课已发布1.2.0，居民文字约定与商户素材核对单分别保留。当前唯一实现说明见[开发者文档第18节](../01-开发者文档.md#18-开放采访样板课实现)。

仍需继续建设的是按成品自动触发的完整发布后情境、其余课程的同等级探索深度、教师创作工具、稳定多学生身份与持续职业画像。旧六个candidate模板、校准样例和其他课程资源不因本轮接线自动启用，也不为提高“使用率”强行放进蟳埔。

**仓库的内容和机制明显多于当前首屏表现出来的内容。最大的差距是人物、材料与事件没有充分编排成学生能主动探索的经历。** 一部分属于配置还未直接进入课程运行，一部分只在独立前测中完成，一部分其实已经接通，只是当前学生尚未触发或入口偏资料列表。

可以给出人物对话覆盖率等局部指标，不能给出可信的“整个项目闲置70%”之类总比例。人物、模板、计划、知识条目、素材文件和课程不是同一单位；同一资源可能服务多个系统，一次行动也不应唤醒所有智能体。

本次检查包括生产源码的声明与消费者、静态课程清单、当前隔离运行目录的JSON快照、前测实现和历史交付说明。没有操作学生页面、切换演示身份、执行模型调用或另开进程读取活动PGlite数据库。SQL部分报告可核实的种子规模与摄入结构，**未取得当前库的实时逐表统计**。

## 3. 当前网站的实际运行快照

### 3.1 正在展示的实例

比对目标为Web4175/API3003的独立演示数据目录`.local/node-access-demo-20260910/data`。本节最后复读时间为**2026-09-11 03:04（北京时间）**；学生继续使用后数量可能变化。读取的是已有持久记录，没有模拟新学生动作。

| 存储对象 | 此快照的记录 |
| --- | --- |
| 世界 | 1个学生行动、1个入队事件、1次结算、1个后果；为门卫交流 |
| 协作 | 1个AgentRun、1个Task、1个Observation、1个Intent；运行方式`deterministic_demo` |
| 人物世界 | 10个NPC、32个计划；31个`pending`、1个`committed`，已选择门卫介绍计划 |
| 对话 | 1段已结算的林师傅Dialogue、2轮，2条`deterministic_rule`回执，未调用模型 |
| 深层协作与评价 | 此初始数据集尚无grounded协作和终评记录，不能由此推定系统没有相应模块 |

门卫相关执行复用`community-source`推理模板，内容适配中还有黄老师到研究者、游客到权利联络人的模板别名。演员身份与模板身份应分开理解；内部模板名不能直接作为人物发言者名。别名关系见[旗舰内容适配](../../packages/course-content/src/xunpu-flagship-content-v3.ts)。

### 3.2 值得处理的时间差

同一快照中的Dialogue记录`elapsedDialogueMinutes=4`，世界快照仍是`elapsedMinutes=0`、`remainingMinutes=55`。这说明至少在这条调用链里，对话局部耗时没有体现为一致的世界截止成本。世界已有时间字段与推进机制，不能写成“完全没有时钟”；但人物日程、邮件到期与采访成本要统一，才能构成可信的机会取舍。本轮只登记，没有修复。

## 4. 最值得补齐的六处连接

### 4.1 人物数量没有转成对话深度

10个人物已含不同目标、拒绝条件、恢复方式、知识和计划。当前一对一多轮只有3人，其余人往往给一次岗位反馈；场景演员又集中在另外3人。学生因此感受到的角色差异小于内容清单中的差异。

`startDialogue`先调用岗位语义判定，只有被接受的`ask/probe/negotiate`才进入Dialogue。因此已选中林师傅时的普通问候仍可能被拦在专业意图解析外。这是开场分层问题，不能只加“你好”三个字的白名单，也不能要求学生背一套通关答复。

### 4.2 前导条件覆盖过宽

当前`field-access-v4.ts`将阿环、黄老师、吴姐都依赖门卫引荐，工坊和店铺也依赖同一条件；游客依赖准入。研究者依赖来源比对事件。该规则实现了用户先前要求的条件准入，但还没有区分商户公共咨询、预约联系、特定活动内部访问等不同方式。

公共联络和编辑节点并非全都锁住，不能说系统只有一个节点；问题在于最直观的人物和空间依赖集中，缺少能形成完整报道的公共替代路径。下一版应按课程世界里的实际权限缩小锁定范围，而不是删除所有条件。

### 4.3 课程写过分支，运行尚未完整消费

现有4条路线、2组灰度取舍和14个节拍不是空标题，已经写了证据、取舍与后果；但生产源码中，对这些字段的直接访问集中在manifest组装与验证。当前的变序行动、固定事件和32个自主计划确实存在，不能把它们抹掉；缺口是把课程设计整体编译成学生能够选择、绕行、恢复和完成的路径。

新设计应优先给这些既有内容补齐发现条件、人物状态、时限、动作后果和替代出口，之后再添加新情节。一次有意义的取舍比十条同义台词更有价值。

### 4.4 知识库较厚，现场使用较薄

106个知识ID并非全部为蟳埔，也不代表106份有原件的来源。内容库可检索、可授权、可追加修订；10项职业任务、8份案例材料和3个深情境都有API与资料页。学生当前更多是在文本列表中接触它们，而非通过“公告有疑点→询问具体人物→拿到不同版本→决定怎样报道”使用它们。

当前作品证据目录仍主要沿用原24条课程来源，资料查询、grounded检索和作品引用没有形成一个统一的、按本人发现与授权变化的材料视图。应补这个使用链，不能靠把所有检索结果塞到首屏或增加长篇反馈解决。

### 4.5 前测的生活事件尚未回到正式世界

前测已经包含阿环临时离开、约好回归续聊、研究者忘发邮件、催办后补发和附件收入采访本等过程。它们由浏览器本地`Simulation`驱动，和正式API状态不等价。最值得复用的是事件语义、界面关系与已有用例；直接复制本地状态机并与后端双写，会造成“画面中到了、数据库里没到”的第二套事实。

### 4.6 评价的后置条件容易被误认为无能力

现有6维评价、教师终裁、学习者模型与4变体第二场已有工程实现，但受到证据充分性、终评与教师决定等条件约束。开场不显示画像不等于它们全被闲置。真正未完成的是D包提出的跨场稳定身份、训练中持续画像、专业作品评价深化及完整教师组织服务。

36项专业复核材料仍是`pending_expert_review`。8个作品样例和6组对抗样例可以用来检查评价是否错误奖励格式或关键词，但开发测试结果不能代替真实教师判断。新增人物不应先换成更多“人格标签”，而应带来更多有依据的观察机会。

## 5. 复用优先级与不宜扩大的工作

| 优先级建议 | 先取用的现有资源 | 学生应看见的变化 |
| --- | --- | --- |
| 首批 | 10个人物设定、120语义样本、已有多轮存储 | 普通问候能接话，角色有不同知识和当前事务，允许反问、告别和重新协商 |
| 首批 | 7节点、11物件、4路线、2组灰度取舍 | 公示栏、公共采访和引荐均可开始；同一任务能有不同信源与成果 |
| 随后 | 32计划、前测离场/回归/邮件、世界时间 | 人物与邮件会按约定变化；学生可等待、催办、另寻来源或缩题 |
| 随后 | SQL内容服务、10岗位任务、8案例材料、3深情境、11来源/采集媒体 | 资料因探索和提问而出现，进入同一采访本、作品引用和发布反馈 |
| 随后 | 6维评价、已有回放、D包身份与教师服务 | 教师能解释不同学生为什么形成不同作品，不再只看到同一流程完成度 |

6个旧候选模板不应为了数量全部激活；能够由现有角色完成的职责优先补好。其他课程保留自己的内容边界。旧骨骼、碰撞和寻路素材已经随节点策略退出运行，是有意取舍，不是当前要抢救的资源。PPT、宣传视频和历史演示截图可继续保存，但不是本轮课程深度的开发优先级。

本轮新取得的两份官方PDF只进入研究资料目录，见[原件登记与哈希](../../资料/04-职业教育依据/05-蟳埔样板课调研来源.md#2-本轮取得的官方原件)。浙传资源仍是可协调的潜在支持，尚未转成真实课程授权、专业复核或学生试用记录，不能计入已拥有内容。
