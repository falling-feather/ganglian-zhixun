## 1. 验收结论

`QA-002 / V1.1.6` 达到的是“技术验收口径成为强合同、真实模型实验可执行、失败可保留、证据可从干净提交生成、教师能在产品中看到同一计划”的基础设施出口：

1. `gold-technical-evidence/1.0.0` 同时约束技术计划、Live 收据、盲评包、证据评估、迁移证明、性能摘要和根清单；
2. 演示固定为 11 分钟、10 步，覆盖教师开班、学生选题/NPC/材料、暴雨、协作、治理、教师决定、终评和回放；
3. 五项跨界面因果只有自动化、时间线和可见界面三类证据同时存在才可通过；
4. 十项 V1.1 技术门必须且只能各出现一次，失败与证据不足不能被 UI 隐藏；
5. A/B/C 真实结构化模型执行器可按同模型、同案件、同知识、同工具和同量规形成 30 条观察、80 条调用收据；
6. 条件标签不进入模型请求，盲评包和条件键分离保存；
7. 第二情境配置结构与题材专用内核扫描可生成证明，无法追溯的创作工时保持 `null / insufficient`；
8. 本地世界行动已有 12 样本 P50/P95 自动化门；
9. 证据生成器要求生成前 Git 已跟踪源文件无改动，并绑定源提交、双情境、模型/策略、验证命令和文件哈希；
10. 教师实验台显示与生成器相同的计划哈希、10 步、5 项因果、10 项门和迁移绑定。

本提交不包含最终 `artifacts/gold-readiness/manifest.json`。原因不是遗漏：清单必须绑定已经提交且无已跟踪改动的源 HEAD，只有本基础设施提交形成后才能生成。`QA-002` 因此继续保持“进行中”。

## 2. 十步演示、五项因果与十项技术门

### 2.1 黄金演示

| 步骤 | 时间 | 核心可见结果 |
| ---: | ---: | --- |
| 1 | 0–1 分 | 教师钉住旗舰发布、版本和哈希并开班 |
| 2 | 1–2 分 | 学生选题与信源计划改变采访机会和待核事实 |
| 3 | 2–3.5 分 | 私有 NPC 采访形成关系、线索、承诺或拒绝 |
| 4 | 3.5–4.5 分 | 材料版本与转写把世界线索接入正式待办 |
| 5 | 4.5–6 分 | 暴雨同时改变场景、时间、优先级和发布约束 |
| 6 | 6–7 分 | 记者与责任编辑交接，成果 R2 进入同一证据链 |
| 7 | 7–8 分 | 四域治理产生 Finding、仲裁与教师门状态 |
| 8 | 8–9 分 | 教师对精确对象和决策哈希作权威决定 |
| 9 | 9–10 分 | 固定评价案件、四路初评和教师逐维终评 |
| 10 | 10–11 分 | 学生查看能力反馈与根行动到后果的因果回放 |

每步均固定 `actor / surface / action / visibleChange / agentContribution / evidenceRefs / verificationRefs / fallback`。Live 不可用时可以切换确定性模型或保留可重试状态，但不能临场编造 NPC 承诺、模型分数或教师决定。

### 2.2 五项因果

1. 操作平台决定改变世界机会；
2. NPC 承诺、拒绝或私有线索反向进入正式工作；
3. 突发事件同时改变课程操作和世界界面；
4. 治理与教师决定形成世界后果；
5. 两个界面的行为进入同一评价案件和因果回放。

`GoldCausalClaimAssessment` 会拒绝把缺少 `automated_test / timeline / visible_ui` 任一项的因果标成通过。核心模式生成器未执行完整 Chromium 时，五项因果保持 `insufficient`；完整模式只有浏览器收据通过才允许三证同时观测。

### 2.3 十项技术门

| 门 | 最低证据 |
| --- | --- |
| 双维度连续 | 自动化、时间线、可见 UI |
| 单一权威世界 | 世界测试、运行轨迹、发布哈希 |
| 模板/实例/任务追踪 | 运行时测试与教师追踪 |
| 受影响集合调度 | 调度测试与 C 组贡献 |
| 岗位私有视野 | 隔离测试与私有 NPC 轨迹 |
| 职业后果 | 浏览器动作、时间线和可见变化 |
| 能力证据与教师复核 | 固定案件、教师逐维 UI 与轨迹 |
| 显式失败恢复 | 失败样本、不补分和重试入口 |

## 3. 真实结构化模型受控执行器

### 3.1 控制变量

六个固定合成案件逐域绑定：

- 公共证据；
- 当前岗位私有证据；
- 权威事实；
- 与权威事实冲突的候选说法；
- 必需写入岗位；
- 固定教师技术锚点。

协议形成案件集、知识快照、工具策略、量规和控制变量哈希。十次重复按相同案件序列轮转；由于六域不能整除十次，前四域出现两次、后两域出现一次，这一限制必须随报告披露。

### 3.2 三组调用量

| 组 | 每次选择 | 10 次调用数 |
| --- | --- | ---: |
| A | 1 个通用职责 | 10 |
| B | 6 个专用职责广播 | 60 |
| C | 1 个受影响专用职责 | 10 |
| 合计 | 30 条组级观察 | 80 |

每次调用要求严格 JSON：可见证据引用、是否尝试正式写入、写入岗位、候选处置、建议分和理由。请求体不含 `conditionCode / experimentId / runBatchId / controlVariablesHash`。

### 3.3 失败和敏感字段

- 输出 JSON 或 Schema 无效：`live_output_contract_invalid`；
- Token 缺失：`live_token_usage_missing`；
- 网络、鉴权、额度、超时和供应方不可用：保留网关错误码；
- 主调用失败：该观察教师建议分、固定技术锚点和绝对差均为 `null`；
- 广播部分失败：观察为 `degraded`，未观测语义计数不补零；
- 原始 Prompt、原始私有证据、完整回复之外的对话、供应方原始请求 ID 和密钥不进入公开证据；
- 请求、输出和供应方请求 ID 只以命名空间哈希进入收据。

当前定向测试用确定性注入端口验证了 80 次成功路径和首调用失败路径；它证明执行器语义，不是实际模型结论。

## 4. 迁移、性能与版本化清单

### 4.1 迁移证明

`transferScenarioV100` 的配置证明观察到：

- 2 个学生岗位；
- 2 个具有 `role_private` 开场信息的 NPC；
- 3 个连续节点；
- 至少 1 项事件策略；
- 至少 1 项教师审批策略；
- 固定评价量规。

受限路径扫描 `apps/web/src`、`packages/agent-runtime/src`、`packages/world-core/src/engine.ts` 和 `structured-world.ts` 中的迁移情境 ID 与标题。题材配置允许存在于 `packages/world-core/src/scenario-experience.ts`，但不能渗入通用 UI、智能体运行时或世界结算。

现有提交历史没有从零创作计时，不能倒推出八小时以内。证明会把架构部分标为通过、创作工时标为证据不足，总状态保持证据不足。

### 4.2 性能

新增 `apps/api/test/gold-performance.test.ts`，每个样本使用新的内存应用、登录和一次有效学生世界命令，只测命令确认时延。定向结果：

| 样本 | P50 | P95 | 最大 | 目标 |
| ---: | ---: | ---: | ---: | ---: |
| 12 | 47.442ms | 64.171ms | 64.171ms | P95 ≤ 500ms |

该结果只代表 Fastify 内存注入环境。Live 模型目标为 P95 ≤ 8 秒；异步进度目标为 1 秒内可见。二者只有真实样本进入证据包后才能给出状态。

### 4.3 生成器和定价

`scripts/generate-gold-readiness-evidence.mjs` 生成计划、验证收据、逐门评估、演示稿、合同报告、可选 Live 报告、盲评包、条件键、迁移证明、性能摘要和根清单。清单具有：

- `productVersion`；
- 40 位 `sourceGitCommit`；
- 旗舰/迁移发布与内容哈希；
- 合同和可选 Live 模型绑定；
- Prompt/策略组合哈希；
- 10 门、5 因果、Live 和迁移汇总；
- 命令、开始时间、耗时、结果摘要和输出哈希；
- 每个证据文件的相对路径、字节数和 SHA-256；
- 排除敏感字段与已知限制。

DeepSeek 价格保存在 `scripts/gold-evidence-pricing.json` 历史快照中。本版快照来源为官方定价页，访问日期为 2026-07-29；`deepseek-v4-flash` 使用每百万输入 cache-miss `0.14` 美元、输出 `0.28` 美元，`deepseek-v4-pro` 使用 `0.435 / 0.87` 美元。未来运行若模型不在快照中必须先重新核价，不能默认为零成本。

## 7. 联调中关闭的问题

| 问题 | 原因 | 修正 |
| --- | --- | --- |
| 本地性能用例超出 Vitest 默认 5 秒 | 12 次样本会重复创建完整内存应用，总测试墙钟约 18 秒 | 保持 12 样本与 500ms 业务目标不变，只把测试自身超时显式设为 30 秒 |
| 工作台类型增加计划后 API/Web 暂时报字段不存在 | 应用类型检查读取上一次共享包 `dist` | 按 monorepo 顺序重建 contracts 与 agent-runtime，再执行应用类型检查 |
| 证据清单无法在同一未提交工作树绑定最终 Git | 任何把当前未提交改动写进清单的做法都会产生伪绑定或自引用 | 基础设施与实际证据分两次提交；清单绑定 `V1.1.6` 源提交，证据进入后续同任务提交 |
| 首次从干净提交运行生成器时报 `ERR_MODULE_NOT_FOUND` | 根级 ESM 脚本按包名导入，但根 package 不声明内部工作区依赖 | `V1.1.7` 改为显式已构建本地 `dist` 入口，新增 `--validate-imports` / `gold:evidence:smoke`，并把导入烟测接入根门 |
| Windows 启动 `pnpm.cmd` 报 `spawn EINVAL` | Node 22 在 `shell:false` 下不能把 `.cmd` 包装器当原生可执行文件启动 | `V1.1.8` 改由当前 Node 加载 `npm_execpath`；spawn 同步/异步错误转为结构化失败结果，运行时烟测通过 |
| 首轮80次Live有66次 `model_output_truncated` | 三组统一320输出Token紧贴正常结构化JSON的约280—300 Token，闭合前容易触发长度门 | 保留首轮全部失败；`V1.1.9` 对三组统一改为640、最多两引用与短理由，并让失败响应的已观测Token/成本进入收据 |
| 第二轮仍有5次B广播截断，且agent-runtime验证误联网 | 5次均打满640/641；普通回归继承 `.env.local` 的Live烟测开关 | 保留75/80完成和失败指标；`V1.1.10` 对三组统一1024，明确公共/相关私有ref，并只对普通回归覆盖`DEEPSEEK_LIVE_SMOKE=0` |
| 浏览器下载等待超时 | Browser 插件未把 Blob 下载暴露为可等待的 download 事件 | 保留该检查为未形成，不伪称通过；使用既有 Playwright 下载回归作为自动化证据 |
| 沙箱内启动开发服务 `spawn EPERM` | esbuild 子进程被 Windows 沙箱阻止 | 经用户批准在沙箱外以同一命令和隔离临时数据目录启动，不跳过构建 |
