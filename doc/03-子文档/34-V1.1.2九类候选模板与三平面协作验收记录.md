## 1. 验收结论

`AI-005` 已达到“候选可准入、实例可隔离、任务可恢复、输出可约束、世界可二验、过程可追踪”的原型出口：

1. 十四类既有模板与九类新增候选进入同一个版本化生产目录；
2. 九类新增项逐一固定独立职责、权限、上下文、输出契约、触发/过滤、消融假设和失败路线；
3. 证据教练、材料理解、评价复核分别在三个业务平面运行一条真实持久链；
4. 六类暂未进入当前黄金路径的候选保持禁用，并以稳定原因证明没有无关模型调用；
5. 辅助结果只形成非公开、需人工采纳的建议，不能成为世界事实或最终成绩；
6. 教师可从目录、实例和追踪投影定位模板、实例、任务、上下文、模型/工具、结构化输出、资源与保留/过滤理由。

本版证明的是九类候选使用同一架构的工程可实现性，不证明二十三类模板都应保留，也不形成多智能体相对简化架构更优的比赛结论。

## 2. 九类候选目录与准入

生产目录当前共二十三项：十四类既有基线保持 `baseline`；三类新模板为 `active / pending_ablation`；六类新模板为 `candidate / design_gate_passed`。活动状态与订阅 `enabled` 必须一致，重复模板版本、未知模板引用或角色/定义/提示词/触发不一致都会在启动校验时失败关闭。

| 平面 | 候选模板 | 当前状态 | 触发或预定触发 | 独立职责 |
| --- | --- | --- | --- | --- |
| 学生辅助 | 课程导航 | 禁用候选 | `node_activated` | 解释当前目标、岗位要求和交付标准 |
| 学生辅助 | 任务规划 | 禁用候选 | `evidence_recorded` | 把学生既定目标拆成步骤与缺失输入 |
| 学生辅助 | 证据教练 | 活动 | `evidence_recorded` | 指出证据缺口、追问和核验路径 |
| 材料生产 | 材料理解 | 活动 | `media_processing_completed` | 把固定处理结果整理为观察、实体、未核声明和来源 |
| 材料生产 | 采访结构化 | 禁用候选 | `media_processing_completed` | 形成待确认纪要、声明和追问清单 |
| 材料生产 | 内容适配 | 禁用候选 | `artifact_revision_saved` | 对固定修订提出渠道适配建议 |
| 教师辅助 | 课程设计 | 禁用候选 | `session_started` | 提出课程草稿差异、缺项和量规建议 |
| 教师辅助 | 实时干预 | 禁用候选 | `evidence_recorded` | 为教师形成最小介入候选 |
| 教师辅助 | 评价复核 | 活动 | `evaluation_arbitrated` | 定位逐维分歧、证据缺口和复核顺序 |

禁用不代表删除，也不代表已经证明无价值。它表示该模板已有可审计的设计准入项，但当前订阅不会建立任务；只有后续内容触发与 `AI-006` 同条件消融能够改变其生命周期。

## 3. 三平面运行链

### 3.1 学生辅助：证据教练

```text
学生 Evidence 进入 WorldEngine
→ evidence_recorded + Outbox
→ 调度器解析证据所属学生实例
→ 只装配该学生岗位安全投影、证据与授权知识
→ assistance/evidence-coach 严格输出
→ WorldEngine 校验主体、角色快照、模板/实例/任务和状态
→ agent_assistance_recorded
```

输出只包含追问、证据缺口和核验路径。它不能确认材料为事实、替学生完成成果、推进节点或提供标准答案。非学生证据不会借用学生实例，而是形成 `instance_inactive` 过滤。

### 3.2 材料生产：材料理解

```text
MediaProcessingTask 进入完成态
→ media_processing_completed + Outbox
→ 调度器按任务请求者和精确任务解析资源实例
→ 固定 media task、材料版本与 inputContentHash
→ assistance/material-understanding 严格输出
→ WorldEngine 复核资源类型、ID、版本和请求者边界
→ agent_assistance_recorded
```

输出中的材料引用与任务资源引用用途不同：前者指向被理解的材料，后者证明本次辅助工作绑定哪一个精确处理任务。声明必须保持 `unverified`，工具观察不能被升级为权威事实。

### 3.3 教师辅助：评价复核

```text
EvaluationArbitration 形成新修订
→ evaluation_arbitrated + Outbox
→ 调度器解析教师辅助实例与精确仲裁资源
→ 固定 evaluationCaseId、arbitrationId、decisionHash 和意见集合
→ assistance/evaluation-review 严格输出
→ WorldEngine 复核案件、仲裁与资源版本
→ agent_assistance_recorded
→ 教师仍以 review_assessment 完成逐维终评
```

评价案件可能先后形成多个仲裁修订。运行与测试都必须选择当前精确 `evaluationCaseId + arbitrationId`，不能把同一案件的早期复核建议误认成最终仲裁建议。

## 4. 权限、输出与世界门

### 4.1 实例和任务快照

每个辅助任务固定：

- `templateRef / instanceRef / taskId / subscriptionId`；
- `definitionVersion / promptVersion / outputSchemaRef`；
- 会话、世代、课程、团队、岗位、主体和私有记忆命名空间；
- 受信任 `roleSnapshot`；
- 可选精确 `resourceRef`；
- 触发事件、根因果、状态版本、派发决策和重试信息。

目录不保存私有记忆，实例不能修改模板，任务执行中不能升级模板版本。教师实例查询从真实持久任务物化；未运行的候选不会生成虚构实例。

### 4.2 建议输出

九种输出是严格判别联合，均要求：

- `authority = advisory_only`；
- `requiresHumanAction = true`；
- 不得使用 `public` 可见域；
- 主体与可见行动者必须匹配实例权限；
- 输出 `kind` 必须匹配模板声明的 Schema；
- 模板特定资源存在时，资源类型、ID 和版本必须精确一致。

课程导航、任务规划、证据教练不能输出标准答案；材料理解、采访结构化不能确认事实；内容适配不能覆盖成果；课程设计不能发布情境；实时干预不能自动干预；评价复核不能给最终分。

### 4.3 并发与追加式提交

辅助任务执行前，编排器同时核对任务期望状态、当前授权投影和最新世界状态。后台任务导致版本前移时，当前尝试按既有机制重试并重新装配上下文，不把过期投影继续交给模型。

世界内核把通过二验的建议作为追加式 `agent_assistance_recorded` 保存。辅助结果不会因另一条建议写入而被覆盖；世界事实、审批、发布和成绩仍由原业务命令、确定性仲裁或教师动作产生。

## 6. 联调中关闭的问题

| 问题 | 原因 | 修正 |
| --- | --- | --- |
| 异步建议推进状态后，后续测试命令偶发 `409` | 后台事件与前台测试动作竞争同一乐观版本 | 测试命令只对明确的版本冲突读取新投影并有限重试；生产世界门不放宽 |
| 材料理解建议的材料引用与任务资源引用被混淆 | 两者分别表示业务材料和本次实例绑定资源 | Schema 与 Handler 分开保存 `materialRef` 和 `media_processing_task resourceRef` |
| 评价复核缺少精确仲裁资源 | 仅有案件信号不足以证明建议针对哪个仲裁修订 | 固定 `evaluation_arbitration / arbitrationId / decisionHash` 并在世界二验 |
| 多个评价仲裁建议被测试误取早期结果 | 同一案件会产生多个合法仲裁修订 | 断言同时匹配 `evaluationCaseId + arbitrationId` |
| 并发辅助任务拿到已过期授权投影 | 任务期望版本与读取投影之间可能有新事件 | 运行前增加任务、投影、最新世界三方一致性守卫，冲突进入可恢复重试 |
| 源码变更后定向测试仍执行旧契约 | 工作区包测试入口读取已构建 `dist` | 先重建相关包，再执行 API 链；完整 `pnpm check` 保持构建前置 |

## 7. 未纳入本版的结论

本版明确不宣称：

1. 九类新增模板已经全部启用或应全部保留；
2. 三类活动模板相对规则、单一通用智能体或合并模板具有显著优势；
3. 已完成每组三十次或每组至少十次的 A/B/C 消融；
4. 已形成无关调用率、P50/P95、Token、成本、教师修订或教师用时统计；
5. 已完成五项跨界面因果、八至十二分钟黄金演示或第二微型情境；
6. 已取得教师间一致性、模型—专家偏差、学生试点或教学效果结论；
7. 已完成科大讯飞关键能力 Live、生产封装、加密、分布式部署或正式 `V1.0.0` 发布。

这些边界与[26-国金成果证明与开发准入标准.md](../02-子文档/26-国金成果证明与开发准入标准.md)一致：架构可运行只是比赛证据的输入，不是最终成果证明。
