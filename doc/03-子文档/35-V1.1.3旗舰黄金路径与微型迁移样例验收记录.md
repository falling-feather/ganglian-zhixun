## 1. 验收结论

`CONTENT-003` 已达到“内容可配置、引用可校验、发布可钉住、两类情境可启动、学生投影不泄密、旧版不被改写”的内容出口：

1. 旗舰七个节点均同时具备课程操作任务、世界互动机会、NPC信息差、智能体贡献、动态事件、阶段成果和能力证据；
2. 七个节点均有同节点的“学生选择 → 智能体贡献 → 世界后果 → 能力证据”四段引用；
3. 黄金内容顺序固定为“选题调研 → NPC采访 → 事实核验 → 暴雨突发 → 双岗协作 → 治理发布 → 评价复盘”；
4. 第二微型情境以两个学生岗位、两个私有NPC、三个节点、一次学生触发事件、一个教师门和一套固定评价复用同一契约；
5. 两份新发布均进入真实目录、API和`WorldEngine`启动路径，没有新增题材专用前端、世界结算或智能体运行时代码；
6. 学生只接收当前节点和当前岗位可见的内容指引，NPC私有视角、信息差、预定智能体贡献和未发生事件保留在服务端。

本版证明的是双维度课程内容能够由同一通用架构承载，并达到 `GAME-002` 可联调状态。它不证明五项跨界面因果已经运行，也不等同于第二情境已经形成完整迁移实验。

## 2. 通用双维度内容契约

共享契约新增 `scenario-experience/1.0.0`，以可选 `experienceDesign` 挂载到现有 `ScenarioPackage`。这样既允许新发布声明双维度内容，也保证没有该字段的旧发布和历史检查点继续解析。

| 契约对象 | 负责表达 |
| --- | --- |
| `scenes / npcInstances / hotspots` | 场景、私有NPC视角、角色可用热点与互动 |
| `operationTasks / worldOpportunities` | 课程操作任务与世界互动机会 |
| `npcInformationGaps / agentContributions` | 信息不对称和可审计的智能体预定贡献 |
| `dynamicEvents` | 触发选择、正式任务、治理或教师门引用 |
| `stageDeliverables / capabilityEvidence` | 阶段成果模板和能力证据来源 |
| `nodeMappings` | 将以上对象绑定到精确情境节点 |
| `causalBranches` | 将学生选择、智能体贡献、世界后果和能力证据闭合在同一节点 |
| `fixedEvaluation` | 精确Rubric、证据来源和教师终评要求 |

目录校验器执行下列失败关闭：

- 所有对象标识唯一，内容版本与情境发布版本一致；
- 旗舰类型正好映射七个节点；微型迁移类型正好包含两个学生、两个NPC实例和三个节点；
- 场景、节点、NPC、热点、岗位、互动、材料、成果模板、证据和Rubric引用必须存在；
- 学生任务只能分配给该情境已配置的学生岗位；
- 世界机会中的选择、动态事件中的触发选择/任务/审批策略必须存在；
- 世界机会必须位于声明当前节点的场景，互动选择必须属于当前热点；因果分支中的学生选择必须真正归属当前节点；
- 每个情境节点必须有映射和至少一条同节点四联因果；
- 微型迁移情境至少使用材料理解或采访结构化贡献，并至少有一项学生触发、受治理或教师门控制的事件；
- 固定评价必须引用发布包中的精确Rubric版本和有效证据来源。

目录复制和安全改版会同步 `experienceDesign.contentVersion`。正文、Actor、ACL、工具和已发布哈希仍受原不可变规则约束。

## 4. 第二微型迁移情境

第二发布为 `scenario-rain-closure-briefing-v1@1.0.0`，题名“古镇暴雨闭园应急融媒通报”。它用于证明同一内容Schema可以承载更小的任务结构，不是新增一门完整课程。

### 4.1 最小配置

- 学生岗位：责任编辑、记者；
- 私有NPC：景区值班员、平台运营员；
- 节点：任务理解、信源采访、治理发布；
- 材料：三份固定输入材料；
- 知识：两条与信源核验、应急通报相关的授权知识；
- 互动：复用既有角色互动契约；
- 智能体贡献：采访结构化；
- 动态事件：学生选择触发闭园通报变化；
- 治理门：复用既有教师世界事件审批策略；
- 评价：固定Rubric、固定证据来源、教师终评必需。

规范内容哈希为：

`bab4410c33c4d2a92082310e3d0651b20054d3d05411b527138a34ee72cd45f1`

### 4.2 配置迁移边界

微型情境复用现有角色契约、权限、材料、RAG、互动命令、目录、API、`WorldEngine`和评价协议。源码中没有加入 `scenario-rain-closure-briefing-v1` 的条件分支，也没有按“暴雨闭园”创建新的前端Store、世界Reducer或智能体Handler。

当前自动化已经证明两个学生岗位均可创建会话并取得安全投影。尚未形成“从学生触发事件到教师最终评价”的完整手工/浏览器运行证据，也没有记录从需求到可运行发布的人工工时，因此本版不能宣称已达到26号标准的完整迁移成果门。

## 5. 角色安全投影与隐私边界

`WorldEngine` 在生成学生 `StateProjection` 时只读取当前节点，并按当前 `RoleBinding` 再次裁剪：

- 只保留分配给该学生岗位的操作任务；
- 只保留该岗位可使用的热点与互动选项；
- 世界机会中不可见的选择引用被移除；
- 阶段交付物和能力证据只返回学生完成任务需要的公开字段；
- 固定评价只返回量规标识、版本、证据引用和“教师终评必需”等元数据。

学生投影明确不包含：

- NPC `privatePerspective`；
- `npcInformationGaps`；
- `agentContributions` 的设计态正文；
- 尚未发生的 `dynamicEvents`；
- 指向私有信息、预定智能体贡献或未发生事件的来源标识；
- 其他岗位的专属任务和不可用互动；
- 教师说明、系统提示词、完整世界状态或服务端配置。

投影的存在不改变权威边界：内容指引只说明“当前可做什么”，实际互动、事件、审批、后果、证据和评价仍须通过原有命令、世界门、事件日志和教师门产生。

## 8. 联调中关闭的问题

| 问题 | 原因 | 修正 |
| --- | --- | --- |
| 暴雨路线最初引用不存在的审批策略 | 内容草稿使用了未登记的策略标识 | 改为复用已存在的教师世界事件审批策略，并由目录交叉校验固定 |
| 微型API启动测试返回`403` | 测试使用的班级/团队不属于当前演示身份授权范围 | 改用既有授权班级和团队；不放宽生产成员、会话或绑定权限 |
| 新契约可能改变旧发布哈希 | 若把双维度字段设为必填或修改旧对象，会破坏不可变快照 | `experienceDesign`保持可选，新内容只发布独立版本，并用哈希回归固定旧对象 |
| 学生可能看到NPC信息差或预定事件 | 直接投影完整内容设计会提前泄露角色私有信息和剧情 | 新增专用学生安全Schema，在世界内核按节点、岗位、热点和互动重新裁剪 |
| 复制情境后内容版本可能仍指向源版本 | 课程指引已有类似版本漂移风险 | 目录复制/改版同时同步`courseGuide.contentVersion`和`experienceDesign.contentVersion` |
| 沙箱内构建出现`spawn EPERM` | esbuild子进程受本机沙箱限制 | 使用已批准的项目构建入口完成同一构建与完整根门；源码和测试未因此放宽 |

## 9. 未纳入本版的结论

本版明确不宣称：

1. 固定2D/2.5D场景、角色位置、关系变化或轻量动效已经实现；
2. 选题、NPC承诺、暴雨、治理发布和评价案件五项跨界面因果已经完整运行；
3. 八至十二分钟黄金演示、刷新恢复和两侧同因果标识已经验收；
4. 微型情境已经从学生触发事件连续运行到治理、教师终评和回放；
5. 已形成迁移人工工时、配置差异报告或平台化复用率；
6. A/B/C消融、能力证据矩阵、评价效度、真实试点或教师负担已经形成；
7. 科大讯飞关键能力Live、生产封装、加密、分布式部署或正式`V1.0.0`发布已经完成。

这些边界与[26-国金成果证明与开发准入标准.md](../02-子文档/26-国金成果证明与开发准入标准.md)一致：配置可复用是迁移成果的必要前提，不是最终比赛证据。
