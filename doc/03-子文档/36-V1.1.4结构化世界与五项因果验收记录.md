## 1. 验收结论

`GAME-002` 已达到“同一投影重建世界、结构化选择进入权威结算、教师门按配置生效、世界后果回到任务与证据、五项因果可从界面/事件/证据三侧对账”的原型出口：

1. 当前场景、阶段、虚拟时间、状态标签、角色/NPC热点、关系、任务、事件卡、七类结果信号、因果回放和证据连续性均来自服务端 `StateProjection`；
2. 学生只能提交配置中的 `choiceRef`，不能自定义目标节点、世界变化、证据、教师门或后果；
3. 世界内核按当前节点、任务岗位和幂等语义校验选择，随后写入选择与证据事件，并按配置建立教师候选或推进世界；
4. 世界任务进入课程侧共享任务抽屉，课程与世界根行动保留同一事件/证据连续性；
5. 选题、NPC承诺、突发事件、治理发布和同一评价连续性五项因果均有通用派生与回归；
6. 固定2D/2.5D视觉不依赖图像生成模型，刷新、模式切换和角色切换不依赖客户端剧情变量；
7. 旗舰 `1.1.0` 与微型 `1.0.0` 内容哈希未改变，源码没有按情境标识或题材添加世界分支。

本版证明的是结构化可演算职业情境世界的原型架构和运行链已经成立。它不证明八至十二分钟黄金演示、迁移人工成本、消融、评价效度、真实试点或完整国金成果已经形成。

## 2. 结构化世界投影

共享契约新增 `structured-world-stage/1.0.0`，并把可选 `structuredWorld` 挂入 `StateProjection`。旧会话或旧投影没有该字段时继续解析，Web 保留安全回退。

| 投影对象 | 来源 | 学生可见内容 |
| --- | --- | --- |
| `scene` | 当前节点映射、虚拟时间、可见后果 | 场景名、阶段、视觉模式、时间和公开状态标签 |
| `hotspots` | 当前岗位可用内容热点与可见互动 | 环境/角色热点、可用选择、NPC关系立场和最近公开回应 |
| `taskStates` | 当前岗位操作任务、世界任务与已发生事件 | 状态、优先级、阻塞原因、来源事件和可执行选择 |
| `eventCards` | 已发生且当前角色可见的配置事件 | 标题、状态、世界变化、任务影响、来源事件 |
| `signals` | 可见互动、事件、任务、证据和材料 | 线索、承诺、约束、材料、风险、后果、能力证据 |
| `causalReplay` | 同一根行动产生的世界事件与证据 | 来源模式、命令、状态区间、事件/证据标识 |
| `evidenceContinuity` | 当前证据、评价案件和教师终评 | 收集中、已固定、教师终评，以及安全计数和来源模式 |

`packages/world-core/src/structured-world.ts` 是纯函数派生层。`WorldEngine` 在调用前先按当前角色裁剪事件、互动、证据和材料，因此派生层不需要接触完整服务端状态，也不能写入世界。场景变化以已经发生的世界事件和配置 `worldChanges` 为依据，不从前端模式、按钮文字或风险值猜测剧情。

## 3. 权威选择与教师门

### 3.1 强类型命令

`record_experience_choice` 只接受：

```text
choiceRef
```

来源模式、界面表面、交互标识、会话、主体、岗位、状态版本和幂等信息继续由既有 API/行动信封链固定。客户端不能提交 `nextNodeId`、`worldChanges`、`evidenceRefs`、`affectedTasks` 或审批策略。

### 3.2 世界结算顺序

```text
学生点击配置选择
→ API 绑定主体和 ActionEnvelope
→ WorldEngine 校验当前节点 / 当前岗位 / 重复选择
→ experience_choice_recorded
→ evidence_recorded
→ 配置要求教师门？
   ├─ 是：CandidateEvent(pending)
   │      → 教师按精确候选批准
   │      → 配置世界变化 / node_activated
   └─ 否：直接提交配置后果或节点推进
→ 新 StateProjection
→ 世界舞台、共享任务、因果回放和证据连续性同步更新
```

学生命令能力使用框架级兼容桥开放，最终授权仍在 `WorldEngine` 中按当前节点任务的 `roleIds` 校验。这样不需要修改 `CONTENT-003` 已发布角色契约，也不会改变发布哈希。

### 3.3 配置优先

候选和批准后的后果优先使用情境配置中的：

- `worldChanges`；
- `affectedOperationTaskIds`；
- `evidenceRefs`；
- `approvalPolicyId`；
- `nextNodeId`。

通用回退只处理缺失的可选摘要，不根据“暴雨”“平台”“古镇”等题材文本选择业务分支。

## 4. 五项跨界面因果

| 编号 | 26号标准要求 | 当前实现链 | 自动化/运行观察 |
| --- | --- | --- | --- |
| 1 | 操作平台选题改变世界人物或采访机会 | 课程根行动、当前任务和信源计划进入世界事件；世界舞台据此改变人物热点、线索与机会状态 | 回归固定信源计划问题可解锁NPC线索/承诺；私有信息不泄漏 |
| 2 | NPC承诺或拒绝进入操作平台待办 | 可见岗位互动派生NPC关系、立场与最近回应；关联任务以 `world_projection` 进入共享任务抽屉 | 回归固定承诺与正式任务状态；两侧读取同一任务标识 |
| 3 | 突发事件同时改变场景与正式任务 | 已发生配置事件改变场景阶段、时间标签、任务优先级、约束和事件卡 | 回归固定突发事件前后阶段、时间、优先级和交付约束变化 |
| 4 | 治理/发布决定改变NPC、平台或后续事件 | 已批准治理/平台事件派生关系、后果信号、事件卡和后续任务 | 回归固定平台关系与配置世界后果，标题来自 `worldChanges` |
| 5 | 两端行为进入同一评价案件 | `causalReplay` 按 `rootActionId` 保留课程/世界来源，事件和证据进入同一 `evidenceContinuity` | 回归固定两个来源根在同一已固定证据连续性中可见 |

上述五项已达到原型级“结构、结算、投影和对账”闭环。正式验收仍需 `QA-002` 为旗舰完整路径固定操作时序、截图、事件/证据标识、刷新恢复和失败样本。

## 5. 世界舞台与共享任务

`apps/web/src/components/student-world-stage.tsx` 以固定CSS层构造：

- 场景远景、中景、工作台和状态氛围；
- 当前阶段、虚拟时间和公开状态标签；
- 环境与角色热点；
- NPC关系、立场和最近回应；
- 世界选择及配置后果预览；
- 共享任务状态和优先级；
- 动态事件卡；
- 七类结果信号；
- 因果回放和证据连续性侧栏。

`buildStudentExperienceModel` 将 `structuredWorld.taskStates` 合并为 `world_projection` 共享任务来源。课程平台和世界舞台仍由一个 `useSessionProjection` 驱动，世界选择与岗位互动仍通过 `App.tsx` 的强类型命令联合入口提交。本地状态仅保存模式、抽屉、选中项和提交中等界面偏好。

教师启动训练会话后，`startTrainingSession` 返回会话摘要。App 先为同课堂、同授权团队的本地身份合并新会话，再刷新 `/api/auth/demo-profiles`。该流程只修正前端新会话可达性；服务端成员、团队、会话和岗位授权没有放宽。

## 6. 角色安全与不可变兼容

学生投影不会包含：

- NPC `privatePerspective` 或信息差设计正文；
- 其他学生岗位的专属任务；
- 不可用互动选项；
- 尚未发生的 `dynamicEvents`；
- 教师说明、教师驳回理由或完整候选载荷；
- 完整评价草稿、私有记忆、提示词、租约或幂等键；
- 服务端配置中的隐藏来源引用。

不可变发布回归：

| 发布 | 结果 |
| --- | --- |
| 旧旗舰 `1.0.0` | 继续使用既有不可变对象与哈希 |
| 旗舰 `1.1.0` | 保持 `100aa9b8fdba95cf88589629e2bf9d1b8a2dce84bcbe7a500234a5defae72e76` |
| 微型迁移 `1.0.0` | 保持 `bab4410c33c4d2a92082310e3d0651b20054d3d05411b527138a34ee72cd45f1` |

世界动作能力通过通用命令桥和任务岗位二次校验实现，没有把新命令写入已发布角色对象。新投影字段为可选，旧会话、旧快照和没有 `experienceDesign` 的情境继续兼容。

## 8. 人工浏览器验收

人工浏览器使用全新临时数据目录、确定性模型和讯飞Mock，按真实界面完成：

1. 教师从微型迁移发布启动新训练会话；
2. 切换学生身份并选择新会话，页面不再因旧授权档案回退；
3. 学生进入“结构化可演算职业情境世界”；
4. 提交“暴雨闭园通报计划”世界选择；
5. 状态版本前进，证据数增加，任务变为等待教师门；
6. 因果回放显示 `record_experience_choice`、两个事件和一项证据；
7. 教师看到精确候选并批准；
8. 学生投影推进到“采访疏散与安置”，世界场景变为“临时安置点采访区”；
9. 后果标题显示配置内容“学生先核定安全事实”，不是旧平台题材硬编码；
10. `390×844` 页面无横向溢出，结构化世界标题、后果和主要交互可见；页面控制台无 warning/error。

浏览器验证证明原型路径可操作、教师门可见、配置后果可回到学生投影。它不是 `QA-002` 的八至十二分钟正式黄金脚本，也没有形成可提交比赛的截图清单。

## 9. 联调中关闭的问题

| 问题 | 原因 | 修正 |
| --- | --- | --- |
| 学生身份看见新会话但选择立即回退 | 开班只更新当前教师档案，本地学生档案仍是旧授权会话列表 | 启动返回会话摘要；同课堂/团队本地档案先乐观合并，再刷新权威档案 |
| 教师批准后的后果标题仍是旧平台审核文案 | 通用节点候选沿用历史默认摘要 | 优先使用配置第一项 `worldChanges`，仅在缺失时回退 |
| 给已发布学生角色增加新命令会改变内容哈希 | 角色命令属于规范内容的一部分 | 删除内容对象修改，改为框架兼容桥加当前节点任务岗位二验 |
| 世界舞台可能提前显示设计态事件 | 若直接读取 `experienceDesign.dynamicEvents` 会泄露未发生剧情 | 事件卡只从已发生且当前角色可见的配置事件派生 |
| 开班后热重载复用旧临时租约 | 首个临时数据目录仍有旧开发进程/租约状态 | 终止旧进程并改用全新临时数据目录完成复验；仓库数据未受影响 |
| E2E 等待旧世界页标题 | 页面标题升级，测试仍固定旧标题 | 更新两处可访问标题断言并完整重跑 Chromium 9/9 |

开发日志中还观察到确定性智能体波对缺失 `agent-teaching` 实例的既有配置告警；它没有造成页面控制台错误、世界选择失败或本轮自动化失败，本提交没有借机扩大到智能体实例治理。`AI-006 / QA-002` 应在批量运行与正式黄金脚本中继续观察并决定是否单独立项。
