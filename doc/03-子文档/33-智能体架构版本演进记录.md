## 2. V0.1.1—V0.3.0：从固定脚本到可信编排

### 2.1 `V0.1.1` 固定脚本纵向原型

最初版本已经具备世界事件、状态版本、角色契约、权限投影、证据和教师复核等外壳，但具名“智能体”的核心行为主要由 `WorldEngine.decide()` 中的固定分支产生：

```text
学生命令
→ 固定 switch / 固定话术 / 固定候选 / 固定分数
→ JSONL 世界事件
→ 角色过滤投影
```

当时尚无真实智能体调度器、节点图、模型路由、RAG 上下文装配、角色私有记忆和调用轨迹。这一历史事实解释了用户所指出的“空有表层”问题，但不代表当前状态。

### 2.2 `V0.1.2—V0.1.3` 首个运行时

`DOC-003` 首次把智能体拆成触发、路由、提示词、模型/检索/工具、守卫和后接节点。随后 `ARCH-002` 建立：

- `packages/agent-runtime/`；
- 版本化图、节点、边、入口和最大步数；
- 六层上下文的早期骨架；
- 策略守卫、结构化 `AgentIntent`、降级与运行轨迹；
- `material_observed` 唤醒事实核查的第一条真实事件波。

这一阶段仍是单进程、有限订阅和确定性模型，不能描述为完整自治多智能体。

### 2.3 `V0.2.0` 真实模型底座

模型调用被统一到 `StructuredModelPort`，DeepSeek V4 作为开发期真实提供方验证网络、结构化 JSON、超时、有限重试和脱敏调用轨迹；科大讯飞星辰 Agent/Workflow 预留 Handler-backed 入口。

关键保留结论是：模型只生成受限业务草稿，可信 ID、角色、受众、世界版本和候选状态由本地运行时与世界内核构造。

### 2.4 `V0.3.0` 可信编排

原命令调用栈被拆为：

```text
可信人类命令 → WorldEvent + Outbox
→ 持久 AgentTask / 租约 / 重试 / 死信
→ 后台 AgentRuntime
→ 结构化结果回到 WorldEngine
```

同时建立服务端 `Principal / RoleBinding`、HttpOnly 会话、CSRF、Outbox 幂等、任务版本迁移、世代隔离和恢复补偿。消息总线从可靠性来源降为唤醒信号。

当时明确保留的限制包括：本地 JSONL、单 Node.js 进程、外部调用至少一次语义和非分布式 fencing。

## 3. V0.4.0—V0.5.1：上下文、角色生态与双导演

### 3.1 `V0.4.0` 权限上下文与私有记忆

建立 `fixed / state / retrieved / evidence / privateMemory / transient` 六层上下文，检索前后双 ACL、整项预算、引用清单、角色私有记忆命名空间和教师上下文调试入口。

重要保留结论：

- 先生成主体可见投影，再做检索；
- 相似度不等于权限；
- 私有记忆按会话世代、团队、行动者和角色隔离；
- 教师调试看清单与哈希，不默认扩散私有正文。

### 3.2 `V0.4.1` 岗位角色生态

两个真人学生岗位与总编、采访对象、版权方、平台运营等角色进入共享 `RoleAgentRuntime`。角色支持追问、拒绝、承诺、工具请求和多轮立场变化，并把语言回复与世界动作分离。

这一阶段取代了“注册了角色名称就算智能体”的旧判断。

### 3.3 `V0.5.0` 版本化课程情境

情境从代码常量迁移为可校验草稿、不可变发布快照和逐会话固定版本：

```text
教师复制/编辑
→ 校验/预览
→ ScenarioRelease(version + contentHash)
→ 会话固定 releaseId
```

旧会话不会因 Catalog 更新而漂移；未知旧版本失败关闭。

### 3.4 `V0.5.1` 双导演

教学导演先根据能力点、节奏和可见证据给出 `TeachingDirective`，情境导演再从发布版路线、冷却和前置条件中形成 `CandidateEvent`。候选仍需世界重验和教师审批。

驳回恢复只接收脱敏请求，不能读取教师私有理由，也不能无限循环地产生替代候选。

## 4. V0.6.0—V0.7.0：内容治理、评价与监督学习

### 4.1 `V0.6.0` 可交互内容生产

内容生产从自动跨过的空节点升级为：

- 成果与不可变修订；
- 分层引用和精确提交；
- 多模态世界任务与工作租约分离；
- 部分成功、失败步骤重试和人工补录；
- 成果—治理—评价之间的版本/哈希引用。

### 4.2 `V0.6.1` 四域治理

同一固定材料真正并行进入事实、版权、内容安全和平台规则四条专业步骤。每条分支执行“规则下限 → 工具 → 模型 → 本地守卫”，形成不可变 Finding，再由确定性优先级仲裁和教师精确版本门收敛。

历史上曾存在“一个核查节点代表全部治理”的表层设计，自本版本起被淘汰。

### 4.3 `V0.7.0` 评价法庭与监督学习

固定成果修订形成 `EvidenceBundle / EvaluationCase`，规则与三个语义评价器分槽运行，确定性仲裁保存分歧与不可用状态，教师按精确版本逐维终评。

终评只生成 `LearningCandidate(status=pending_review)`，候选经离线回放、人工审核、独立版本发布和追加式回滚后才可成为正式学习制品。

“模型直接给最终总分”与“自学习自动修改课程/提示词”的旧想法在此明确淘汰。

## 5. V0.8.0—V0.9.4：追踪、控制、恢复与发布

### 5.1 `V0.8.0—V0.8.1` 双时间线与版本一致性

世界事件、Outbox、任务、调度尝试、运行、节点、模型、工具和死信被投影为教师专属的世界/执行双时间线，支持筛选、因果聚焦、深链和响应式详情。

服务端只返回白名单摘要和哈希，学生访问拒绝；原始载荷、完整 Prompt、私有记忆、教师说明、密钥、租约 token 和幂等键不进入调试投影。`V0.8.1` 补齐 API/Web/manifest 的版本一致性自动门。

### 5.2 `V0.9.0` 会话控制面

建立 `Classroom / TeamInstance / TrainingSessionRecord / SessionMembership`，岗位绑定由有效成员关系派生；A/B 会话、控制面、状态、追踪和健康均按授权隔离。

身份切换、会话切换和岗位切换被明确拆开，动态会话授权不再依赖字符串前缀。

### 5.3 `V0.9.1` 恢复检查点

检查点引入规范 JSON SHA-256、组件哈希、进度锚点、来源回退拒绝、Agent → Media 恢复顺序、跨会话失败隔离、clean close 和教师检查点控制。

检查点证明“同一状态可恢复”，不把本地 JSONL 包装成生产数据库或在线灾备。

### 5.4 `V0.9.2` 全浏览器闭环

8 条真实 Chromium 串行用例覆盖教师配置、动态开班、多人多岗、岗位协作、多模态四域治理、成果评价、监督学习、`scene_completed`、回滚和新会话；5 条故障矩阵覆盖篡改、未来来源、排空失败和授权拒绝。

completion-gate lane 只改变任务领取顺序，防止评价/学习被导演任务饿死，不修改持久优先级、租约或业务语义。

### 5.5 `V0.9.3` 本地单写者与停机恢复

同一规范 `DATA_DIR` 在任何写入前取得本机协作进程独占租约；私有记忆和被引用对象进入 integrity v2；backup/verify/restore 按完整目录逐文件校验并只恢复到不存在的新目标。

这不是多主机分布式锁、在线快照、加密备份或生产灾备。

### 5.6 `V0.9.4` 发布控制面

生产构建演示、全新目录 frozen install、官方 Chromium、full clean-room、跨版本业务状态升级/回滚和机器可读收据被放在八层业务架构之外。

发布脚本只能断言、启动、停机、备份和归档，不能改变世界事件。HEAD、锁文件、收据、annotated tag 和归档必须指向同一候选源。

| “Mock/端口存在等于讯飞 Live” | 已淘汰 | 未配置真实 Handler/凭证时显式 mock、manual 或 unavailable |

## 8. 维护规则

以后出现以下内容时写入本文件或 03 主文档，而不是再次追加到 04：

- 已完成版本的实现摘要；
- 已被替代的路由、提示词、数据模型或部署假设；
- 一次性测试数字、浏览器验收和发布收据；
- 提交、标签、回滚与事故修正记录。

只有当前仍有效的架构、边界和最新进度才进入 04。历史事实如需完整逐字复核，以 Git 快照为准，不从记忆重写。
